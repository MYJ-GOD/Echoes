# 后端静态代码审查模板（规范性优先）

## 1. 审查目标

- 在不运行项目的前提下，仅通过阅读代码与配置，识别质量风险与规范偏差。
- 输出可直接落地的问题清单，支持按优先级排期修复。
- 识别安全隐患、配置风险、数据一致性问题。
- 推动代码质量持续改进，降低技术债务积累。

## 2. 审查边界（强约束）

- 只审查：源码、配置、脚本、SQL、文档中的实现约束。
- 不执行：构建、测试、启动服务、外部 API 调用、数据库连接。
- 不做：性能压测结论、运行态行为结论（仅可标记为”需运行验证”）。
- 不覆盖：UI/UX 细节、业务逻辑正确性验证（需测试保证）。

## 3. 规范基线（审查依据）

### 3.1 语言规范

- 命名清晰且语义一致（类/方法/变量/常量）。
- 类型与空值处理明确，避免隐式约定。
- 异常使用统一（异常类型、抛出边界、错误语义）。
- 注释聚焦”为什么”，避免重复”代码做了什么”。
- 方法行数控制（建议 ≤50 行），单一职责。
- 嵌套深度控制（建议 ≤3 层）。

### 3.2 工程规范

- 分层清晰（Controller / Service / Repository / Domain）。
- 依赖方向单向，禁止底层反向依赖上层。
- 单文件单职责，避免 God Class / 巨型方法。
- 公共逻辑可复用，避免复制粘贴分叉实现。
- 模块边界清晰，禁止跨层直接调用。
- 接口与实现分离，依赖抽象而非具体实现。

### 3.3 团队规范

- 对齐仓库既有约定（目录结构、DTO/VO/PO 使用边界、返回结构）。
- 对齐统一错误码、日志字段、接口字段命名。
- 对齐代码评审约定（必填项、阻断项、可后续优化项）。
- 对齐 Git 提交规范（Commit Message 格式）。

### 3.4 API 设计规范

- RESTful 语义正确（动词、资源命名、HTTP Method）。
- 接口版本管理（/api/v1/...）。
- 请求参数校验（@Valid / 自定义校验器）。
- 响应结构统一（code/message/data）。
- 分页参数规范（page/size/sort）。
- 文档注解完整（@Operation / @ApiModelProperty）。
- 幂等性保证（写操作需考虑重复请求）。
- 超时与重试策略（外部调用需配置）。

### 3.5 安全编码规范

- 输入验证原则（永远不信任外部输入）。
- 输出编码原则（XSS 防护）。
- 参数化查询（SQL 注入防护）。
- 最小权限原则（接口鉴权）。
- 敏感数据脱敏（日志、响应）。
- 安全默认值（fail-safe defaults）。

## 4. 审查顺序（从高风险到低风险）

1. 核心业务链路（交易/会话/关键状态流转）
2. 数据访问层（事务、幂等、读写一致性）
3. 鉴权与输入处理（认证、授权、参数校验）
4. 公共基础能力（工具类、公共组件、跨模块依赖）
5. 边缘模块（低调用频次、后台任务、辅助接口）

## 5. 单文件 10 项检查点

> 每个文件必须逐项检查；命中即记录问题，不做”主观感觉良好”判定。

1. **可读性**：命名、方法长度、注释是否支持理解。
2. **复杂度**：分支层级、嵌套深度、条件组合是否过重。
3. **重复代码**：重复逻辑是否应抽取为公共能力。
4. **边界处理**：空值、默认值、枚举兜底、非法输入处理是否完整。
5. **错误处理**：异常吞没、错误码不一致、错误语义不清晰。
6. **安全风险**：输入未校验、敏感信息泄露、权限边界不明确。
7. **可维护性**：扩展点、职责边界、模块耦合度是否合理。
8. **一致性**：风格、返回结构、日志规范、分层模式是否统一。
9. **数据一致性**：事务边界、乐观锁、并发控制、缓存一致性。
10. **资源管理**：Stream/Connection 关闭、内存泄漏风险、连接池配置。

## 5.1 代码细节检查清单

- [ ] 无 `System.out.println`（应使用 logger）
- [ ] 无空的 catch 块（吞掉异常）
- [ ] 无魔法值（应抽取为常量/枚举）
- [ ] 无过长的参数列表（>5 个参数应考虑对象封装）
- [ ] 无过度嵌套（if 嵌套 >3 层应考虑提前 return）
- [ ] 无 God Method（方法行数 >100 应重构）
- [ ] 无时间耦合（时区处理、时间戳精度）
- [ ] 无资源泄漏（Stream/Connection 未关闭）
- [ ] 无并发隐患（共享变量未加锁、ThreadLocal 未清理）
- [ ] 无 deprecated API 使用

## 6. 专项审查清单

### 6.1 安全审查专项

- [ ] 敏感信息硬编码检查（密码、密钥、API Token）
- [ ] SQL 注入风险（动态 SQL 拼接）
- [ ] 命令注入风险（Runtime.exec / os.system 等）
- [ ] 路径遍历风险（文件上传/下载路径校验）
- [ ] SSRF 风险（外部 URL 请求未校验）
- [ ] 反序列化风险（不可信数据来源）
- [ ] 日志信息泄露（敏感数据脱敏）
- [ ] 接口鉴权缺失（@PreAuthorize / 权限注解）
- [ ] CORS 配置过宽（allow_origins: "*"）
- [ ] 速率限制缺失（易受 DDoS 攻击）
- [ ] CSRF 防护（表单提交）
- [ ] 文件上传校验（类型、大小、病毒扫描）

### 6.2 配置审查专项

- [ ] 环境分离配置（dev/test/prod）
- [ ] 敏感配置是否使用环境变量或配置中心
- [ ] 数据库连接池配置（最大连接数、超时）
- [ ] 日志级别配置（生产环境不应为 DEBUG）
- [ ] 外部服务地址是否可配置（非硬编码）
- [ ] 特性开关（Feature Flag）支持
- [ ] 配置默认值是否安全（fallback 值）
- [ ] 超时配置合理（连接超时、读取超时）
- [ ] 重试策略配置（次数、间隔、退避）
- [ ] 线程池配置（核心线程数、队列大小）

### 6.3 可观测性审查专项

- [ ] 关键链路日志完整（TraceID 透传）
- [ ] 指标埋点（请求数、延迟、错误率）
- [ ] 健康检查接口（/health /ready）
- [ ] 审计日志（敏感操作记录）
- [ ] 链路追踪支持（OpenTelemetry / SkyWalking）
- [ ] 日志级别使用合理（ERROR/WARN/INFO/DEBUG）
- [ ] 异常堆栈记录完整
- [ ] 慢查询日志支持

### 6.4 依赖管理审查

- [ ] 依赖版本锁定（无 LATEST/SNAPSHOT）
- [ ] 无重复依赖声明
- [ ] 无循环依赖（模块间）
- [ ] 第三方库许可证检查（MIT/Apache/GPL）
- [ ] 已知 CVE 漏洞扫描
- [ ] 无未使用的依赖
- [ ] BOM 统一管理依赖版本

### 6.5 数据库审查专项

- [ ] 索引覆盖合理（避免全表扫描）
- [ ] 无 N+1 查询问题
- [ ] 批量操作使用批量语句
- [ ] 事务粒度合理（避免大事务）
- [ ] 软删除字段支持（deleted 标记）
- [ ] 审计字段（created_at/updated_at/created_by）
- [ ] 字符集统一（utf8mb4）
- [ ] 无 SELECT *（明确字段列表）
- [ ] 外键约束合理（引用完整性）
- [ ] 默认值设置合理
- [ ] 字段注释完整

### 6.6 缓存使用审查

- [ ] 缓存键设计合理（避免冲突）
- [ ] 缓存过期时间设置（避免永不过期）
- [ ] 缓存穿透防护（布隆过滤器/空值缓存）
- [ ] 缓存击穿防护（互斥锁）
- [ ] 缓存雪崩防护（过期时间随机化）
- [ ] 缓存一致性策略（更新/删除）
- [ ] 大 Key 识别与治理
- [ ] 热 Key 识别与处理

## 7. 问题分级标准

- **P0（阻断）**：高概率导致数据错误、安全风险、核心流程失效。必须立即修复，否则禁止上线。
- **P1（严重）**：高概率缺陷或明显提升维护成本，短期应修复。需在当前迭代内解决。
- **P2（一般）**：规范偏差、可读性与一致性问题，可排期治理。纳入技术债务 backlog。
- **P3（建议）**：优化建议，不影响功能。可视资源情况处理。

## 7.1 问题定级参考表

| 问题类型 | P0 | P1 | P2 |
|---------|----|----|----|
| 安全 | 明文密码、SQL 注入 | 未鉴权接口 | CORS 过宽 |
| 数据 | 事务缺失、数据丢失 | 并发竞争 | 字段缺失注释 |
| 性能 | 内存泄漏、N+1 查询 | 无索引查询 | 大 Key 缓存 |
| 可维护 | 循环依赖、God Class | 重复代码 | 命名不规范 |
| 稳定性 | 无错误处理 | 无超时配置 | 日志不完整 |

## 8. 问题记录模板（逐条）

```md
### [P?] 问题标题
- **文件位置**：`path/to/file.ext:line`
- **违反规范**：`语言规范/工程规范/团队规范/安全规范` + 具体条款
- **风险说明**：说明可能影响（功能、数据、维护、安全）
- **证据片段**：简述关键代码行为（不贴大段代码）
- **最小修复建议**：给出可执行且范围最小的改法
- **修复优先级**：`P0 | P1 | P2 | P3`
- **相关 CWE**：`CWE-XXX`（如适用，参考 CWE-25 安全弱点分类）
- **修复预估工时**：`Xh`
- **影响范围**：`模块/接口/表`
- **备注**：`需运行验证 / 依赖上下游确认`（如有）
```

## 8.1 问题记录示例

```md
### [P0] SQL 注入风险 - 动态拼接查询
- **文件位置**：`src/main/java/com/echoes/user/UserService.java:45`
- **违反规范**：`安全规范` - 参数化查询原则
- **风险说明**：用户输入直接拼接到 SQL 语句，可能导致 SQL 注入攻击，造成数据泄露或篡改
- **证据片段**：`String sql = "SELECT * FROM users WHERE name = '" + userName + "'"`
- **最小修复建议**：使用 PreparedStatement 或 MyBatis #{} 参数化语法
- **修复优先级**：`P0`
- **相关 CWE**：`CWE-89 (SQL Injection)`
- **修复预估工时**：`1h`
- **影响范围**：用户查询接口
```

## 10. 审查执行清单（可直接打勾）

### 审查前准备
- [ ] 已确认审查范围和边界
- [ ] 已确认”仅静态审查，不运行任何代码”
- [ ] 已获取最新的代码版本
- [ ] 已准备审查记录表格/工具

### 审查执行
- [ ] 已按”高风险 -> 低风险”顺序完成模块审查
- [ ] 已覆盖所有专项审查清单（安全/配置/数据库/缓存/可观测性/依赖）
- [ ] 每个文件均完成 10 项检查点
- [ ] 代码细节检查清单已逐项核对

### 问题记录
- [ ] 所有问题均包含：位置、规范条款、风险、修复建议、优先级
- [ ] P0/P1 问题已标注 CWE 编号（如适用）
- [ ] 已估算修复工时
- [ ] 已识别影响范围

### 输出交付
- [ ] 已输出”问题清单 + 规范差距报告”
- [ ] 已完成修复排期建议并指定责任人
- [ ] 已输出审查结论（总体风险判断）
- [ ] 已安排复审时间

### 跟踪闭环
- [ ] 已创建追踪 issue（JIRA/GitHub Issue）
- [ ] 已关联相关 MR/PR
- [ ] 已安排修复验证
- [ ] 已更新规范文档（如有新增）

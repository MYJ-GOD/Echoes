## 🔴 严重问题 (Critical)

### 1. 微信支付工具类混用两种依赖注入方式

**文件**: `echoes-service-user/src/main/java/com/echoes/user/common/util/WeChatPayUtil.java:38-39`

```java
@Component
public class WeChatPayUtil {
    @Autowired  // ❌ 与 @RequiredArgsConstructor 混用
    private WeChatProperties weChatProperties;
```

**问题**:
- 类已使用 Lombok 的 `@RequiredArgsConstructor`，但同时混用了 `@Autowired` 字段注入
- 字段注入不利于单元测试，推荐使用构造器注入

**建议修复**:
```java
@RequiredArgsConstructor
public class WeChatPayUtil {
    private final WeChatProperties weChatProperties;
}
```

**影响**: 代码风格不一致，降低可测试性

### 2. 硬编码路径和魔法字符串

**文件**: `echoes-service-voice/src/main/java/com/echoes/voice/domain/voice/service/impl/VoiceTrainingServiceImpl.java:388-394`

```java
String baseDir = String.format("D:%sstmp%s", java.io.File.separator, java.io.File.separator);
```

**问题**:
- 硬编码绝对路径 (`D:\stmp`)
- 未使用配置类管理路径

```java
@Value("${echoes.voice.temp-dir:}")

String baseDir = tempDir != null ? tempDir : System.getProperty("java.io.tmpdir");
```

### 5. 异常处理吞没

**文件**: `ChatStreamApplicationService.java:115-122`

```java
try {
    var conv = conversationSessionRepository.findById(sessionId).orElse(null);
    if (conv != null && (conv.getIsDeleted() == null || conv.getIsDeleted() == 0)) {
        userIdRef.set(conv.getUserId());

    // ❌ 异常被吞没，userIdRef 可能为 null

```

**问题**:
- 数据库查询失败后静默处理
- 后续代码可能因 `userIdRef.get() == null` 而失败

**建议修复**:
```java
} catch (Exception e) {
    log.error("Failed to resolve userId from conversation_session", e);
    throw new BusinessException("会话数据查询失败");
}
```

### 6. 资源未关闭（潜在的）

**文件**: `WeChatPayUtil.java:86-93`

```java
CloseableHttpResponse response = httpClient.execute(httpPost);
try {
    String bodyAsString = EntityUtils.toString(response.getEntity());
    return bodyAsString;
} finally {
    httpClient.close();  // ❌ 只关闭了 client
    response.close();    // ✅ 正确关闭了 response
```

**评价**: `response` 已正确关闭，但 `httpClient` 每次请求都创建新实例，性能低下。

### 7. 数据库查询无分页

**文件**: `VoiceTrainingServiceImpl.java:221-237`

```java
public Page<TrainingTaskVO> listUserTasks(UUID userId, String status, int pageNum, int pageSize) {
    List<VoiceTrainingTask> tasks = ...; // ❌ 查询全部数据
    List<TrainingTaskVO> voList = tasks.stream()...;
    Page<TrainingTaskVO> resultPage = new Page<>(pageNum, pageSize);
    resultPage.setRecords(voList);
    resultPage.setTotal(voList.size()); // ❌ 总数是查询后的列表大小
    return resultPage;
}
```

**问题**:
- 先查询全部数据，再在内存中分页
- 当用户任务多时会导致内存溢出

**建议修复**: 使用 MyBatis-Plus 的分页方法
```java
Page<VoiceTrainingTask> page = trainingTaskMapper.selectPage(
    new Page<>(pageNum, pageSize),
    new LambdaQueryWrapper<VoiceTrainingTask>()
        .eq(VoiceTrainingTask::getUserId, userId)
);
```

### 9. 序列化异常处理不当

**文件**: `JwtAuthenticationFilter.java:140-150`

```java
try {
    Result<Object> result = Result.error(message);
    String body = objectMapper.writeValueAsString(result);
    // ...
} catch (Exception e) {
    log.error("序列化错误响应失败", e);
    String body = "{\"code\": 401, \"msg\": \"" + message + "\"}";  // ❌ 手动拼接 JSON
}
```

**问题**:
- 手动拼接 JSON 可能导致注入风险
- 如果 `message` 包含双引号，会破坏响应格式

**建议修复**:
```java
} catch (Exception e) {
    log.error("序列化错误响应失败", e);
    String body = "{\"code\": 401, \"msg\": " + objectMapper.writeValueAsString(message) + "}";
}
```

### 10. 事务注解使用不当

**文件**: `AuthServiceImpl.java:60`

```java
@Transactional(rollbackFor = Exception.class)
public UserLoginVO login(UserLoginDTO loginDTO) {
```

**问题**:
- `login` 方法主要是查询操作，不需要事务
- 自动注册逻辑（补全 Auth 信息）才需要事务

**建议**: 拆分事务边界
```java
public UserLoginVO login(UserLoginDTO loginDTO) {
    UserAuth userAuth = queryAuth(loginDTO);
    if (userAuth == null) {
        repairAuth(loginDTO); // 单独事务
    }
    // ...
}
```

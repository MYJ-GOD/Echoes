## 0. 项目概述

### 0.1 一句话定位

> 双击打开 → 选一个声音（克隆或现成）→ **随时**说话 → 它记得你们聊过的**一切**，而且记错的**时候能改**。

三个关键词：**随时**（托盘常驻 + 全局快捷键）、**一切**（原文 + 摘要 + 事实三层都留）、**能改**（记忆可见可编辑、可追责）。

### 0.2 核心体验（七条，不可协商）

| # | 体验 | 说明 |
|---|---|---|
| 1 | 语音优先 | 主要交互是说话，不是打字 |
| 2 | 音色绑定 | 绑定音色绝不静默替换；失败明确报错 |
| 3 | 连续记忆 | 隔天再聊，记得昨天说的偏好 |
| 4 | **引擎对等可选** | LLM / ASR / TTS 三条链各自可选云端或本地，无主次之分；选定后不被静默替换 |
| 5 | 历史可追溯 | 任何一次对话都能翻回去，原文一字不差 |
| 6 | 记忆可见可控 | 能看见记住了什么，能改、能删、能加 |
| 7 | 随时在场 | 全局快捷键唤起；关窗口不退出 |

### 0.3 三条铁律

1. **单机单用户，永不联网协作**：无账号、无登录、无云同步、无分享链接；唯一跨设备通道是局域网第二终端（WS + token）。**此条约束的是"协作与存储"，不约束"推理是否走云端"**——云端只做无状态推理，不保存对话、不建账号、不形成云端数据资产；对话原文始终只存在于本机数据库。

2. **三条链对等可选，选择必须显式且可见**：
   - LLM / ASR / TTS 各自独立选择云端或本地，**没有主次之分**，也不设"必须本地可用"的强制底线。
   - 用户选定的路径不得被静默替换：选了本地不走云端，选了云端不偷偷降级。
   - 当前生效路径必须可见：界面上能看清每条链走的是云端还是本地、云端时数据发往哪个 provider。
   - 云端不可用时**报错并给出明确替代方案**，不自动改变用户的选择（与铁律 3 一致）。

3. **音色与记忆，绝不静默变更**：`ready` 态合成失败必须报错，不得改用内置音色；检索不到的 / 被取代的 / 已删除的记忆不得进入 prompt；任何降级回退必须留痕且用户可见。

### 0.4 目标与非目标

**A. 永久放弃**：多用户 / 多租户 / 账号体系 / 云同步 / 公网访问 / 管理后台 / 移动端 / 虚拟人动画 / 微服务拆分 / 分布式基础设施。

**B. 现在不做但留接口**：

| 项 | 延到 | 前置条件 |
|---|---|---|
| 意图路由 `task` 分支 + 工具调用 | R4 之后 | 主动开口定案 |
| 主动开口（定时问候/久未联系） | R4 之后 | ADR-007 定案 |
| 免提全双工（VAD + AEC） | 无排期 | VAD 直接用 silero-vad（10.6k★, MIT，现成预训练模型）；AEC/降噪调研 speexdsp（xiph）；回声消除方案验证 |
| 人格多档预设 | R4（v1.1） | 现版可编辑人设已够用 |

**C. 原为"非目标"，现提升为必做**：会话历史/会话列表（R1c）、多音色管理（R2a）、记忆管理界面（R3a）。

## 1. 系统架构

### 1.1 三层结构（依赖单向）

```
┌─────────────────────────────────────────┐
│  Vue 3 前端（渲染层）                     │
│  无业务逻辑，所有状态来自 Rust            │
│  ★ 麦克风采集也在这里（getUserMedia）     │
└──────────────┬──────────────────────────┘
               │ Tauri invoke / event
┌──────────────▼──────────────────────────┐
│  Rust 外壳（系统层）                      │
│  窗口 / 播放 / 托盘 / 快捷键 / 凭据       │
│  ★ 只做播放与 DSP，不做录音               │
└──────────────┬──────────────────────────┘
               │ stdio / WS（JSON 行协议）
┌──────────────▼──────────────────────────┐
│  Python sidecar（能力层 + 编排层）        │
│  唯一状态源：SQLite                      │
│  core → db → engines → memory → orchestration → ipc
└─────────────────────────────────────────┘
```

### 1.2 架构约束

**沿用（冻结契约）**：sidecar 是唯一状态源；依赖方向单向（`import-linter` 强制）；契约单一来源（Pydantic → TS 自动生成，`ipc:check` 挂 build 前）；协议只增不改。

**新增**：
- **引擎可热切换**：设置变更下一轮生效，不重启进程（§3.3）。
- **原文必须落盘**：任何进入 LLM 的文本都必须可回溯（§2）。

## 2. 数据模型变更

### 2.1 前提变更声明（BREAKING-DECISION）

原设计明确写了「轮次明细不落库」：

| 位置 | 原文 |
|---|---|
| `db/migrations/0001_init.sql:28` | `-- 会话（轮次明细不落库，落库的是摘要与事实）` |
| `orchestration/graph.py:409` | `"""turn 收尾落库（5.1：轮次明细不落库，只更新活跃时间与音色绑定）。"""` |

本计划引入 `turn` 表 = **主动推翻该决策**。

- 定性：`BREAKING-DECISION`（SQL 层是新建表，语义层是否定原设计前提）
- 处置：母文档 §5.1 该条注释必须在 R1a 合并前改写；两个 `.sql` / `.py` 注释同步更新
- 连带：`session_summary.up_to_turn` 的语义从"内存序号"改为"turn 表 seq"（见 §2.4）；**存量值必须在 0003 中重置为 0**（旧摘要文本仍然有效，只是计数基准归零），否则旧会话新 seq 从 1 重来、对比 `up_to_turn=37` 会认为摘要不需要更新，直到再攒满 37 轮
- 连带：`memory_fact.source_turn` 是同一套旧内存序号；0003 新增 `source_turn_id`，旧行保留 `source_turn` 但 UI 标「旧版本记录，无原文链接」，避免来源回溯指到错误的新 turn

### 2.2 迁移 0003：turn 原文层

```sql
-- ============================================================
-- 0003_turn.sql —— 原文落盘（推翻 §5.1「轮次明细不落库」）
-- ============================================================

CREATE TABLE turn (
    rowid          INTEGER PRIMARY KEY,   -- FTS5 external content 依赖 rowid 稳定，禁止省略
    turn_id        TEXT NOT NULL UNIQUE,
    session_id     TEXT NOT NULL REFERENCES session(id) ON DELETE CASCADE,
    -- 冗余存 profile：与 session/memory_fact 口径一致，避免每次检索都 join
    profile_id     TEXT NOT NULL DEFAULT 'default',
    seq            INTEGER NOT NULL,
    user_text      TEXT NOT NULL,
    assistant_text TEXT,
    -- jieba 预分词结果（空格分隔）。unicode61 无法直接切中文，见 2.5
    tokens         TEXT NOT NULL DEFAULT '',
    -- pending 是中间态：turn 开始即 INSERT（原文落盘优先于记录完整），收尾 UPDATE 为终态
    -- 原文落盘的保证范围从 ASR 返回/文本输入起；ASR 阶段崩溃不承诺保留（不引入 transcribing 态）
    status         TEXT NOT NULL CHECK (status IN ('pending', 'complete', 'cancelled', 'failed')),
    fail_reason    TEXT,                   -- crash_cleanup | llm | tts | storage；failed 时填
    voice_id       TEXT,                   -- 当轮生效音色（复现用）
    model          TEXT,                   -- 当轮 LLM（复现用）
    persona_id     TEXT,                   -- 当轮人设（复现用；人设可中途换，不 join）
    latency_ms     INTEGER,
    started_at     REAL NOT NULL,
    ended_at       REAL,
    -- 重说/换一句：append-only，指向替换它的 turn（见 7.8）
    superseded_by  TEXT REFERENCES turn(turn_id) ON DELETE SET NULL
);

CREATE UNIQUE INDEX idx_turn_session_seq ON turn(session_id, seq);
CREATE INDEX        idx_turn_started     ON turn(started_at DESC);
CREATE INDEX        idx_turn_profile     ON turn(profile_id, started_at DESC);
CREATE INDEX        idx_turn_superseded  ON turn(superseded_by)
    WHERE superseded_by IS NOT NULL;

-- 显式 rowid 的原因：VACUUM 可能重排无显式 INTEGER PRIMARY KEY 表的 rowid
-- （SQLite 文档明示），而 turn_fts 以 content_rowid='rowid' 关联；显式 rowid 后
-- rowid 与 turn_id 一一对应，VACUUM / 备份还原均安全。

-- 全文检索：索引 user_text（原文展示用）与 tokens（中文检索用）
CREATE VIRTUAL TABLE turn_fts USING fts5(
    user_text,
    tokens,
    content='turn',
    content_rowid='rowid',
    tokenize='unicode61'
);

-- external content 表必须配三个触发器，否则 FTS 永远为空
CREATE TRIGGER turn_ai AFTER INSERT ON turn BEGIN
    INSERT INTO turn_fts(rowid, user_text, tokens)
    VALUES (new.rowid, new.user_text, new.tokens);
END;

CREATE TRIGGER turn_ad AFTER DELETE ON turn BEGIN
    INSERT INTO turn_fts(turn_fts, rowid, user_text, tokens)
    VALUES ('delete', old.rowid, old.user_text, old.tokens);
END;

CREATE TRIGGER turn_au AFTER UPDATE ON turn BEGIN
    INSERT INTO turn_fts(turn_fts, rowid, user_text, tokens)
    VALUES ('delete', old.rowid, old.user_text, old.tokens);
    INSERT INTO turn_fts(rowid, user_text, tokens)
    VALUES (new.rowid, new.user_text, new.tokens);
END;

-- 原文分块 + 向量（先建表不填充，对话量到千条后开启）
CREATE TABLE turn_chunk (
    chunk_id        TEXT PRIMARY KEY,
    turn_id         TEXT NOT NULL REFERENCES turn(turn_id) ON DELETE CASCADE,
    chunk_idx       INTEGER NOT NULL,
    text            TEXT NOT NULL,
    embedding       BLOB NOT NULL,
    -- 必记：换 embedding 模型后维度不同，混用会崩
    embedding_model TEXT NOT NULL,
    embedding_dim   INTEGER NOT NULL,
    created_at      REAL NOT NULL
);

CREATE INDEX idx_turn_chunk_turn ON turn_chunk(turn_id);

-- turn_chunk 向量形态（本轮定稿）：
-- 1) 仍用 BLOB + sqlite-vec 距离函数暴力扫描；启用填充时 ≤ 2k turns / 每轮 ≤ 2 chunks，
--    1k chunks 的检索预算写为 < 50ms（首次实测后校准）；
-- 2) 超过 10k chunks 再引入 turn_vec（vec0 ANN），本轮只建表不填；
-- 3) RRF 粒度：chunk 命中先归并回 turn_id 去重，再与 turn 级 FTS 在 turn 粒度融合。

-- 来源回溯：本轮注入了哪些记忆（R3a 写入/UI，R1a 建表）
CREATE TABLE turn_memory_ref (
    turn_id TEXT NOT NULL REFERENCES turn(turn_id) ON DELETE CASCADE,
    fact_id TEXT NOT NULL REFERENCES memory_fact(id) ON DELETE CASCADE,
    weight  REAL,
    PRIMARY KEY (turn_id, fact_id)
);
CREATE INDEX idx_turn_memory_ref_fact ON turn_memory_ref(fact_id);

-- session 补两列
ALTER TABLE session ADD COLUMN title TEXT;
ALTER TABLE session ADD COLUMN archived_at REAL;

-- 旧记忆来源序号降级：source_turn 保留为旧内存序号，新抽取只写 source_turn_id；
-- UI 对 source_turn 非空且 source_turn_id 为空的行标注「旧版本记录，无原文链接」。
ALTER TABLE memory_fact ADD COLUMN source_turn_id TEXT
    REFERENCES turn(turn_id) ON DELETE SET NULL;

-- session_summary 外键补 ON DELETE CASCADE（0001 未带；重建表，避免「删会话」被摘要挡住）
CREATE TABLE session_summary_new (
    session_id    TEXT PRIMARY KEY,
    summary       TEXT NOT NULL,
    up_to_turn    INTEGER NOT NULL,
    updated_at    REAL NOT NULL,
    FOREIGN KEY (session_id) REFERENCES session(id) ON DELETE CASCADE
);
INSERT INTO session_summary_new (session_id, summary, up_to_turn, updated_at)
SELECT session_id, summary, up_to_turn, updated_at FROM session_summary;
DROP TABLE session_summary;
ALTER TABLE session_summary_new RENAME TO session_summary;

-- 旧库存量摘要的计数基准归零：up_to_turn 原是内存序号（可能已到 37），
-- turn 表落地后 seq 从 1 重来，不重置则旧会话摘要永不再更新（见 2.1 连带）
UPDATE session_summary SET up_to_turn = 0;
```

**归档与删除语义（必须区分，不可混用）**：

| 操作 | 行为 | turn 是否保留 |
|---|---|---|
| 归档（默认） | 写 `archived_at`，会话从列表隐藏 | ✅ 保留 |
| 彻底删除 | `DELETE FROM session` → `ON DELETE CASCADE` 连锁删 turn / chunk | ❌ 删除 |

UI 上"删除"必须是两步：先归档，再在归档区提供"彻底删除"，且二次确认。

**引用方删除策略（0003 定稿）**：

| 引用方 | 策略 | 说明 |
|---|---|---|
| `session_summary.session_id` | `ON DELETE CASCADE`（0003 重建） | 防御纵深；`SessionRepo.delete` 仍显式先删 summary |
| `turn` / `turn_chunk` / `turn_memory_ref` | `ON DELETE CASCADE` | 已有 / 本轮补 |
| `session.voice_id → voice` | 删除被绑定 voice → 拒绝 `VOICE_IN_USE`；历史 turn 引用不阻塞 | `turn.voice_id` 无 FK，展示走「已删除音色」fallback |
| `memory_fact` | `turn_memory_ref.fact_id` CASCADE；`source_turn_id` SET NULL | 事实比会话长寿，删除会话不删全局事实 |

> **风险**：FK 若运行期未开启，`DELETE` 会静默留下孤儿 summary。FK=ON 与 FK=OFF 两种分支都要测。

**turn 的写入时机（两段式，配合 pending 态）**：`TurnRepo.insert`（turn 开始：status=pending、user_text 已知、assistant_text 为 NULL）→ `TurnRepo.finish`（收尾：终态 + assistant_text/latency_ms/ended_at）。**原文落盘优先于记录完整**——崩溃时 pending 行保有 user_text，宁可残缺不可丢失。崩溃残留的 pending 行由**启动清洗**统一置为 failed（`assistant_text` 保持 NULL，`ended_at`/`fail_reason='crash_cleanup'` 写入，见 §10.4）。`tokens` 在 INSERT 时按 user_text 分词，finish 时并入 assistant_text 重算（`turn_au` 触发器自动同步 FTS）。

**status / superseded 语义（定稿）**：

| 状态 | 语义 | 历史/检索可见性 |
|---|---|---|
| `pending` | turn 进行中；崩溃后由启动清洗置 failed | 默认不可见 |
| `complete` | 正常完成 | 可见 |
| `cancelled` | 用户三跳打断/手动取消；`assistant_text` 存已生成部分 | 可见，标「已打断」 |
| `failed` | LLM/TTS/存储失败或崩溃清洗；`fail_reason` 记录来源 | 默认可见但标失败；不进入三层检索 |
| `superseded_by` 非空 | 被重说/编辑替换 | 默认排除出历史列表、全文搜索与三层检索；仅「查看完整历史」可见 |

> `superseded_by` 非空行若仍进入检索，旧话会回灌 prompt，违反铁律 3；R1c/R3a/R3b 共用这条排除规则。
>
> **检索过滤（定稿）**：三层检索用 `status IN ('complete', 'cancelled') AND superseded_by IS NULL`；历史列表/全文搜索默认含 `complete/cancelled/failed`（`pending` 不可见，`superseded` 默认隐藏），但不进入三层检索。「查看完整历史」可显示 pending/superseded。

### 2.3 迁移 0004：voice 表重建

`voice.sample_path` 是 `TEXT NOT NULL`（`0001_init.sql:21`），而**云端音色没有样本文件**，直接 INSERT 会失败。SQLite 不支持 `ALTER COLUMN`，只能重建表。

```sql
-- ============================================================
-- 0004_voice_kind.sql —— 支持云端音色（sample_path 改为可空）
-- 注意：本脚本不含 BEGIN/COMMIT 与 PRAGMA foreign_keys——事务与外键开关
--       由迁移 runner 统一管理（PRAGMA foreign_keys 在事务内是 no-op，
--       必须在事务外设置，见 2.6；脚本内自带事务会与 runner 包的事务冲突）
-- ============================================================

CREATE TABLE voice_new (
    id            TEXT PRIMARY KEY,
    display_name  TEXT NOT NULL,
    sample_path   TEXT,                     -- ← 改为可空：云端音色无本地样本
    model_path    TEXT,
    status        TEXT NOT NULL,            -- training | ready | failed
    quality_score REAL,
    created_at    REAL NOT NULL,
    kind          TEXT NOT NULL DEFAULT 'cloned',   -- cloned | builtin | cloud
    provider      TEXT,                     -- cloud 时必填；本地为 NULL
    engine        TEXT NOT NULL DEFAULT 'cosyvoice2' -- 本地引擎：cosyvoice2 | gpt-sovits；cloud 时为 provider
);

INSERT INTO voice_new
    (id, display_name, sample_path, model_path, status, quality_score, created_at, kind, provider, engine)
SELECT
    id, display_name, sample_path, model_path, status, quality_score, created_at, 'cloned', NULL, 'cosyvoice2'
FROM voice;

DROP TABLE voice;
ALTER TABLE voice_new RENAME TO voice;
```

> **音色单一真相源**：所有可选音色（`builtin:default` 除外）一律入 `voice` 表；`SettingsView.tts_voice` 只是当前选中的 `voice_id`，`session.voice_id` FK 继续成立。云音色写 `kind='cloud'` + `provider` + `engine=provider`；本地克隆音色写 `engine='cosyvoice2' | 'gpt-sovits'`。

> **类型连带**：`VoiceRow.sample_path` / `VoiceView` 必须改 `Optional[str]`；`VoiceRow` 增 `engine: str`，`VoiceView` 增 `kind` / `provider` / `engine`；`_voice_from_row` 用 `_opt_text`，禁止 `_text(None)` 产出字符串 `"None"`。TS 类型随 `ipc:check` 重新生成。

> ⚠️ **重建外键风险**：`session.voice_id REFERENCES voice(id)`。外键 ON 时 `DROP TABLE voice` 会对引用表做隐式检查而失败，因此外键开关必须由 runner 在**事务外**统一处理：`apply_migrations` 全程 `foreign_keys=OFF`，全部迁移完成后 `ON` 并执行 `PRAGMA foreign_key_check`，**非空即视为迁移失败**（口径见 §2.6）。

### 2.4 turn 序号的权威来源

**现状缺陷**：`graph.py:84` 的 `turn_seq` 是 `Session` 内存字段，`:183` 是 `session.turn_seq += 1` **纯内存自增**。而 `session_summary.up_to_turn`（`0001_init.sql:58`）已把旧序号落库。

```
第一次运行：turn_seq 累加到 37，摘要表 up_to_turn=37
关闭应用（内存清零）
第二次运行：turn_seq 从 1 开始
  → INSERT (session_id, seq=1) 撞 UNIQUE idx_turn_session_seq
  → 或摘要 up_to_turn=37 指向错误范围
```

**定案**：`turn_seq` 的权威来源改为数据库。

```python
# db/repo.py 新增
class TurnRepo:
    def next_seq(self, session_id: str) -> int:
        row = self._conn.execute(
            "SELECT COALESCE(MAX(seq), 0) + 1 FROM turn WHERE session_id = ?",
            (session_id,),
        ).fetchone()
        return int(row[0])
```

`Session.turn_seq` 降级为**本轮缓存**，每轮 begin 时由 `TurnRepo.next_seq()` 赋值，不再自增。

**并发约束（定稿）**：`next_seq` 与 `insert` 必须在同一 `BEGIN IMMEDIATE` 事务（或同一单写线程）内完成；`MAX(seq)+1` 的两步读写在打断重说、局域网第二终端 WS 等并发场景下会撞 `idx_turn_session_seq`。`_open_session` / `_persist_session` 的写路径同样纳入单写者原则。

**连带修正**：`_schedule_summary(session, turn_seq)` 与 `_schedule_memory(..., turn_seq)` 的入参来源同步改为该值（现状传的是内存自增值）。

### 2.5 中文全文检索方案

| 方案 | 结论 |
|---|---|
| `tokenize='unicode61'` 直接索引原文 | ✗ 连续汉字聚成**单个 token**（"我今天学了吉他"是一个 token），搜"吉他"命中 0 |
| `tokenize='trigram'` | ⚠️ 需 SQLite ≥3.34（bundled 满足），但**查询词须 ≥3 字符**；中文两字词"吉他""咖啡""乐队"全部检索不到 |
| **jieba 预分词写入 `tokens` 列** | ✓ 采用 |

**实现**：写入 `turn` 时对 `user_text + assistant_text` 做 `jieba.cut(..., cut_all=False)`，以空格拼接存入 `tokens`；检索时对 query 同样分词后 `MATCH`。因 turn 是两段式写入（§2.2），INSERT 时 tokens 只含 user_text，`finish` 时并入 assistant_text 重算——`turn_au` 触发器会同步 FTS 索引，无需手工维护。

**查询规范（R1a 必做）**：FTS5 默认 `AND`，中文助词（的/了/我/是/吗）会让查询零命中。查询侧同样 jieba 分词后去 stopword，用 `OR` 召回，再由 R1c/R3 排序；两字词保留原文短语查询。命中 `tokens`（assistant 内容）而展示 `user_text` 时 snippet 不会高亮——展示层改为「命中于回复内容」或展示 assistant 片段。

**打包注意**：`jieba` 的词典是数据文件，PyInstaller 冻结版必须显式收集（`--collect-data jieba` 或等价配置），否则 `tokens` 生成会在真机静默退化为空。

**新增依赖**：`jieba`（纯 Python，无编译负担），需在 `sidecar/pyproject.toml` 声明并同步 `uv.lock`。

### 2.6 迁移纪律（数据安全）

桌面应用升级失败会直接毁用户数据，因此迁移必须是"可回退"的：

1. **仅当存在待执行迁移时**：检查空余空间 ≥ 库大小 × 1.2；不足则拒绝迁移并保留旧库。空间足够时 `VACUUM INTO '<data_dir>/backup/<version>-<ts>.db'`
2. **事务与外键由 runner 统一管理，迁移脚本内禁止 `BEGIN`/`COMMIT`/`PRAGMA foreign_keys`**：
   - runner 把每条迁移包成**一个事务**：`executescript("BEGIN;\n<sql>\nPRAGMA user_version=N;\nCOMMIT;")`——`user_version` 与脚本改动同事务提交，崩溃后重跑安全。现状 `connection.py:175` 的裸 `executescript` 不提供整段原子性，半途失败会留下 "table already exists" 的死局（重试三次都撞，且下次启动仍撞）；`user_version` 的修改在 SQLite 中是事务性的，可安全并入
   - 外键开关必须在事务外（`PRAGMA foreign_keys` 在事务内是 no-op）：`apply_migrations` 全程 `foreign_keys=OFF`，结束后 `ON` 并执行 `PRAGMA foreign_key_check` + `INSERT INTO turn_fts(turn_fts) VALUES('integrity-check')`，任一非空即报 `MIGRATION_FAILED`；`finally` 必须恢复 FK=ON
   - **失败不自动还原**：回滚事务 → 保留备份 → 写 `migration_failed` 标记 → 进入 RECOVERY 态（见下）
   - 现有 `_MIGRATION_ATTEMPTS=3` 只保留给多实例竞争；RECOVERY 不依赖它循环重试
3. 存量数据修正随迁移一并执行（如 §2.2 的 `up_to_turn` 归零、`source_turn_id` 新列），修正语句与 DDL 同事务
4. 成功后保留最近 3 份备份，超出自动清理
5. 设置页「数据」区展示备份列表与"从备份还原"入口（R5 补 UI，R1a 先落能力）

**失败恢复态（RECOVERY，建议方案；§11 决策 7 确认后定稿）**：

```
迁移失败 → 回滚 → 保留备份（不自动还原）→ 写 migration_failed 标记（数据目录文件，非 DB）
→ 进入 RECOVERY：
   - 不自动重试（或仅重试 1 次）
   - 启动检测到 RECOVERY → fatal 恢复页：「打开备份目录 / 从备份还原 / 退出」
   - restore 前：关闭连接、删除 -wal/-shm
   - user_version 高于代码支持 → 同样进恢复页
验收口径：旧版本能打开备份库 + 新版本展示恢复页，不做无限重试
（删去旧口径「数据能从备份完整还原」——它只证明文件还原，不证明新版本可用）
```

### 2.7 turn 写入失败策略（定稿）

1. `TurnRepo.insert` 失败（磁盘满 / 锁超时）：**不静默丢**——本轮继续（语音体验不断），气泡标「未保存」，上报 `HISTORY_WRITE_FAILED`；连续失败 ≥ 3 转入只读模式（可看历史/记忆，不能对话）。
2. `TurnRepo.finish` 必须在 `turn_complete` 事件之前 commit；否则 UI 显示完成、DB 仍 pending，崩溃清洗会误标 failed。
3. 启动清洗（pending → failed）在任何新 turn 之前执行；`assistant_text` 保持 NULL，写 `ended_at` 与 `fail_reason='crash_cleanup'`。
4. 验收：`turn_complete` 发出后立刻 kill 进程，重启后该 turn 为 `complete`；DB 无 `status='pending'` 残留。

## 3. 引擎矩阵

### 3.1 三条链，各自独立可选

**LLM / ASR / TTS 是三条独立链路，任一条可单独切云端或本地，互不绑定。**

| 链路 | 本地 | 云端 |
|---|---|---|
| **LLM** | Ollama（qwen3 / llama / gemma 全系）、llama.cpp | 任意 OpenAI 兼容端点（OpenAI / DeepSeek / Moonshot / 智谱 / 硅基流动 / DashScope）、Anthropic、Gemini |
| **ASR** | faster-whisper（tiny～large-v3）、SenseVoice-small、Paraformer | OpenAI `whisper-1` / `gpt-4o-transcribe`、豆包（火山）、DashScope、讯飞 |
| **TTS** | CosyVoice2-0.5B（官方只有 0.5B；**instruct 支持情感/方言/语速控制**，R4 情感表达直接用）、GPT-SoVITS、Kokoro（官方模型仅英文，中文 v1.0 不用） | OpenAI `tts-1` / `tts-1-hd` / `gpt-4o-mini-tts`、火山豆包语音、MiniMax、ElevenLabs、Azure、**edge-tts**（免费免 Key、原生流式；⚠️ **LGPLv3** + 逆向 Edge 接口 + 服务端可能封 IP，见 §3.6） |

> **edge-tts 合规**：许可证是 **LGPLv3**（不是 MIT），且逆向微软 Edge 接口、无 SLA，近期存在服务端封 IP/`NoAudioReceived` 问题。**R2a 不默认、不随安装包分发**；最多作为用户自行安装的外部工具，或直接弃用。

**实现原则：OpenAI 兼容优先**——一个 `openai_compat` 适配器覆盖大半云端。清单不锁死。

**云端价值**：现成音色库 + 首包通常更小（本地 CosyVoice2 的首包受模型解码速度限制；以实测为准）；中文识别质量；大模型质量。

**本地价值**：完全离线、无月费、数据不出机、不受网络抖动影响；代价是首次要下运行时（体积与加载时间）。

**两者对等**：不设强制底线。三条链各自独立选择，由用户在首次启动时明确选择、之后可随时切换（核心体验第 4 条）。产品不做"必须能离线跑完"的承诺，但**必须让用户清楚自己选了哪条路**。

### 3.2 版本选择与预设

**两层**：模型档位（下拉，本地从 `ollama list` / 模型目录扫描，云端填 Key 后拉 `GET /v1/models`）+ 质量预设（一键套用）。

| 预设 | LLM | ASR | TTS | 适用 |
|---|---|---|---|---|
| **云端（首次默认）** | 所选云端 | 本地 whisper（建议默认；云端需逐链同意） | 云端 | 开箱即用：无需下载运行时，填 Key 就能说话；设置页展示预估月费量级 |
| **本地（离线）** | Ollama | whisper small | CosyVoice2-0.5B | 隐私优先、无月费、常断网；首次需下运行时 |
| **混合** | 云端大模型 | 本地 whisper | 云端高品质音色 | 识别不出机、生成走云端 |

> **为什么首次默认是「云端」**：既然不设"必须本地可用"的底线，就不该强迫新用户先下数百 MB 运行时才能说第一句话。本地档作为**显式选项**存在，由用户在首启向导中选择（也可以在向导里直接选本地）。
> **云端 ≠ 免同意**：云端路径意味着录音/文本发往第三方（含 edge-tts）。首启向导必须逐链勾选「我知晓语音数据将发送至第三方」；未勾选的链路强制本地或不可用。ASR 建议默认本地（原始录音出境门槛最高），LLM/TTS 可默认云端；已有用户升级不得静默切云。`privacy_mode` 语义定为全链路强制本地、本地不可用即报错，而不是禁用语音功能。
> **成本必须可视**：云端档在设置页展示"预估月费量级"与本次会话用量，不能只在账单里才发现。
> **三条链独立可改**：预设只是一键套用，用户可选"预设 + 任意单链覆盖"，覆盖后预设标记为 `custom`。

### 3.3 热切换契约

**问题**：`--llm / --asr / --tts` 是 sidecar 启动参数，改一个必须重启进程，与人设"保存后下一轮生效"不一致。

**目标语义**：

```
设置页修改 → 写 setting 表
  → 壳发 config.changed 事件（仅用于 UI 即时刷新展示；热切换本体不依赖它）
  → 编排层在【下一轮 turn 开始时】读取新配置（既有拉取语义，settings_loader 已每轮执行）
  → 新引擎实例按需懒加载
      ├─ 成功 → 切换
      └─ 失败 → 保留旧实例 + 报 ENGINE_SWITCH_FAILED
  → 进行中的 turn 不受影响，用旧引擎走完
```

> **为什么不用事件驱动切换**：拉取语义（§3.4）已经存在且每轮必经，事件丢失或时序错乱都不会造成"配置已改但引擎没换"；`config.changed` 只是让设置页不必等下一轮对话才刷新状态展示。**不得做成两套通知机制**——事件只是展示层的加速器，权威路径永远是每轮拉取。

**扩展点**：`graph.py::_apply_runtime_settings`（:242）已存在，R2a 只在此方法内扩三条链。**R1a 不得修改该方法体**（避免与 R2a 冲突，见 §7.0）。

**`SettingsView` 扩展草案**：

```rust
pub struct SettingsView {
    // ---- 现有 ----
```

### 3.4 降级与失败语义

**总原则：任何链路都不自动切换。** 切换意味着路径改变——音色会变、质量会变、**数据去向会变**。因此统一处理为「报错 + 一键切换」，由用户决定。

| 场景 | 行为 | 用户可见 |
|---|---|---|
| 云端 TTS 不可达 | 不自动回落 → 报错 + 「改用本地音色重试」 | 明确提示，绝不静默换声 |
| 云端 ASR 超时 | 不自动回落 → 报错 + 「改用本地识别重试」 | 明确提示 + 一键切换 |
| 云端 LLM 失败 | 不自动回落 → 报错 + 「改用本地模型重试」 | 明确提示 + 一键切换 |
| 本地模型缺失 | 引导下载，显示体积 | 进度条 + 「或改用云端」 |
| 本地运行时未安装 | 引导安装（显示体积）或「改用云端」 | 明确二选一，不默认代选 |
| Key 失效（401） | 归类 `AUTH_FAILED`，设置页高亮 + 一键重填 | 明确指引 |
| 云端 TTS 返回 MP3/Opus | 解码 + 重采样为 PCM16（16k/24k）后再入 `AudioChunk`；解码位置（sidecar Python vs Rust）列为 §11 决策 8 | 统一 AudioChunk，不让播放层感知 provider |
| 云端 ASR 文件上传 | OpenAI ASR 是 multipart，不属于 `openai_compat`（chat）；拆 `openai_chat` / `openai_audio` 两个适配器 | 避免把 chat 适配器硬套到 audio |
| 历史写入失败 | 本轮继续，气泡标「未保存」，报 `HISTORY_WRITE_FAILED`；连续失败 ≥3 转只读 | 不静默丢原文（§2.7） |
| 删除被绑定音色 | 拒绝 `VOICE_IN_USE`，提示先切换音色或确认解绑 | 避免历史会话引用悬空 |
| 引擎热切换失败 | 保留旧实例，报 `ENGINE_SWITCH_FAILED`；设置页标「待生效（切换失败）」 | 旧引擎继续可用，实际路径可见 |
| 三条链全部不可用 | 只读模式：可看历史、可看记忆，不能对话 | 说明原因 + 修复入口 |

> **多凭证**：`secrets.rs` 现仅 `llm-api-key`；扩为 `asr-<provider>` / `tts-<provider>` 条目，keyring 分项管理；`asr_has_key` / `tts_has_key` 由此生成。

> 与旧版的差别：不再有"云端 ASR 超时自动回本地"这类隐式回落。**数据去向的改变必须由用户知情并同意**，这与铁律 2、铁律 3 是同一条原则的三个面向。

### 3.5 通用化与扩展性（底座参考与外部对标）

> 本项目的长期定位是**通用语音伴侣底座**：三条引擎链云端/本地强可插拔，Echoes 是底座上的第一个应用。本节登记开源世界的对标项目与取舍，作为 R2a/R2b 引擎矩阵的架构参照。

**引擎标识命名空间（契约级约定）**：引擎统一标识为 `local:<model>` / `cloud:<provider>[:<model>]`（如 `local:cosyvoice2-0.5b` / `cloud:openai:gpt-4o-mini-tts`），写入 setting 表与 `SettingsView`。新增引擎实现 = 新增一个标识 + 一个适配器文件，**不改编排层与契约**（注册表化）。

**外部对标**：完整项目清单、许可证、维护状态与用途统一登记在 **§3.6**；本节只保留架构取舍，不再重复 star 数。

**不引入整包的三条原则**（贯穿本计划全部取舍）：

1. 与"SQLite 唯一状态源 + 单机单用户"冲突的不引入（mem0 / Letta / Zep 等自带存储抽象的记忆框架）
2. 与 sidecar 分层依赖方向冲突的不引入（Pipecat / LiveKit Agents / NeMo Guardrails 整包）
3. 研究代码不直接依赖、只抄架构（VoiceMem）

## 4. 记忆系统 v2

### 4.1 三层模型

| 层 | 载体 | 时间尺度 | 回答什么问题 | 现状 |
|---|---|---|---|---|
| 短期：原文窗口 | `turn` 表 | 最近 N 轮 / token 预算内 | 「刚才说到哪了」 | ❌ R1a 落地 |
| 中期：会话摘要 | `session_summary` | 每会话一条滚动摘要 | 「上周那次聊了什么」 | ⚠️ 表有、生成有、已注入 prompt（`graph.py:230-232`）；缺检索出口与管理 UI |
| 长期：事实 | `memory_fact` | 跨会话，可被取代 | 「我是谁、我喜欢什么」 | ✅ 有，含 supersede |

**关键点**：短期层必须是**落盘的原文**，不是内存数组——它同时是 RAG 原料和历史页数据源。

### 4.2 检索链路（五段）

```
① Query Rewrite（条件触发）
     仅 memory_recall 意图或检测到指代（它/那/这个/上次说的）时执行；
     R3a 先用指代词/正则门控，R4 接入意图路由；
     「它怎么样」→「你上次说的那本书怎么样」
     取最近 3 条 turn，temperature=0，失败原样返回
     （200–800ms + 成本，不做每轮默认）

② 粗召回（高召回优先）
     向量 recall_k=30 ＋ FTS5(BM25) recall_k=30
     → RRF 融合（k=60）→ 候选池 30 条
     （R3a 先落 FTS + 摘要检索；向量/RRF 的向量部分归 R3b）

③ 精排
     bge-reranker-base（CPU 可跑）→ top_k=3~5

④ 阈值门禁
     最高分 < θ → 返回空（宁可不注入，也不注入噪音）
     ⚠️ θ 必须在 13.3 评测集上重标（现 52 例：
        sidecar/tests/fixtures/memory_eval/cases.jsonl）
        不能照搬 v1 的 0.5 —— 那只对 bge-m3 1024 维 + bge-reranker-v2-m3 成立

⑤ 实体加分
     rerank 输出先 min-max / sigmoid 归一化；
     final = rerank_norm + min(entity_hits × 0.1, 0.3)，再重排
     （直接在 logits 上加 0.1 无意义）
```

**检索对象扩展**：

| 问题类型 | 查哪 |
|---|---|
| 「我是谁 / 我喜欢什么」 | `memory_fact` |
| 「上次聊的那个书叫什么」 | `turn` 原文（`turn_fts` + 向量） |
| 「我们上周在聊什么」 | `session_summary` |

**摘要检索机制（定稿）**：「我们上周在聊什么」按 `session.title` + `session_summary.summary` 的 FTS + 时间范围过滤（最近 N 个会话），不把全部摘要无差别注入；R3a 任务 3.3a 落地。

### 4.3 分层注入与 token 预算

```
system prompt
  ├─ 人格（persona）
  ├─ 长期事实（⑤ 结果，≤ 300 token）
  ├─ 中期摘要（当前 + 相邻会话，≤ 400 token）
  └─ 短期原文（最近 N 轮，剩余预算，占大头）
```

k 不再硬编码（现 `graph.py:222` 的 `k=5`），按 `context_window` 预算动态计算。

**落地条件**：300/400 token 预算需要 per-model tokenizer + `context_window` 元数据（SettingsView / 引擎元数据补一列）；落地前用字符近似（≈1 token / 1.5 汉字）并标注误差；`_fit_budget` 的字符口径改造列入 R3a 任务 3.1。

### 4.4 记忆可见性

| 功能 | 说明 |
|---|---|
| 分类分组 | 偏好 / 人物 / 事件 / 属性 |
| 每条显示 | 内容、来源会话（可点进原文）、创建时间、是否已被取代 |
| 操作 | 编辑、删除、合并重复、手动添加 |
| **来源回溯** | 回复气泡长按 → 显示本轮注入了哪些记忆 → 点进去看原话 |

来源回溯的数据落地：新增关联表 `turn_memory_ref(turn_id, fact_id)`，便于按 fact 反查"哪些回复用过它"。

### 4.5 外部对标（R3a/R3b 参考，抄设计不引入）

> 许可证/维护/用途见 §3.6；本节只保留借鉴点。

| 项目 | 规模 | 借鉴点 |
|---|---|---|
| **VoiceMem**（xzf-thu，技术报告 v0.0.2） | 2.8k★，研究代码 | ⭐ 与本项目场景对口（语音+情感+实时+陪伴）的**流式双脑记忆**：① **左脑事实 / 右脑情感分库**——右脑区分"临时情绪"与"长期特质"（Identity 节点 + 情感绑定 Joint 节点），本项目的情感记忆形态在 R3a/R3b 定案时对齐 ② **检索预算按 voice 场景校准**：最终注入 top-5 足够（text agent 灌 top-100 的做法在语音场景是错的），其自报 LoCoMo 91.2%@top-5 ③ **检索藏进 VAD 静默窗口**（自报 134ms 端到端）——检索延迟预算的参照，不是承诺 ④ 评测用 **LoCoMo** 基准 |

## 5. Agent 能力

### 5.1 意图路由（三级，正则优先）

| 意图 | 触发 | 策略差异 |
|---|---|---|
| `chat` | 默认 | 普通生成 |
| `emotional_support` | 正则（好难过/撑不下去/很焦虑…）→ 语义 → LLM | 不检索事实，优先共情，人格切"温柔"档 |
| `memory_recall` | 正则（还记得/你说过/上次/我告诉过你…） | **强制**走检索；检索不中明确说"我不记得"，不许编 |
| `profile_query` | 正则（我是个什么人/你眼中的我…） | 聚合画像，检索 top-10 事实 |
| `task` | LLM 判定 | 工具调用（L3，暂不做） |

**实现顺序**：先正则层（零成本、零延迟、覆盖 60% 场景），语义层与 LLM 兜底后置。v1 的 `intent_router.py` 正则规则可直接复用。**语义层现成件**：`semantic-router`（4.0k★，MIT，本地 FastEmbed 向量路由，毫秒级；默认英文 encoder，中文要换 `bge-small-zh` 等）——正则之后不想上 LLM 判定时的中间档，登记为 R4 候选，v1.0 不用。

### 5.2 Grounding Check（反幻觉）

- 逐 claim 校验是否被注入记忆支撑，输出 `{faithful, score, unsupported_claims}`
- **不阻塞主链路**：异步质检写日志，累计"记忆幻觉率"
- `unsupported_claims` 非空 → 气泡标不显眼标记，点开看详情
- v1 的 judge 设计可直接复用

### 5.3 工具调用（L3，暂不做）

v1 的 ReAct 循环（`AGENT_MAX_ITERATIONS=3`）+ `task` 意图依赖主动开口定案，本轮不排期。

### 5.4 情感链路（检测 → 记忆 → 表达，R4 / v1.1）

全链路尽量用现成件，但**不宣称“零自研”**：中文情感检测仍需要 LLM 或中文情感模型，英文 HF 模型只作兜底。许可证/维护见 §3.6。

| 段 | 方案 | 说明 |
|---|---|---|
| **检测**（文本→情感） | **中文主路径：LLM prompt 或中文情感模型**；英文兜底：`j-hartmann/emotion-english-distilroberta-base`（**6 基本情绪 + neutral，共 7 类**，仅英文，license 未声明） | GoEmotions 是 **数据集**（58k Reddit，27+neutral）+ BERT baseline，**不是现成模型**；只能用于评测/微调。中文不要把英文模型当主路径 |
| **记忆**（情感→画像） | 按 §4.5 VoiceMem 右脑形态：区分临时情绪 vs 长期特质 | 存储形态（`memory_fact` 扩 category 还是独立表）R3b 定案；v1.0 不做情感记忆 |
| **表达**（情感→语音） | **CosyVoice2-0.5B instruct**（§3.1 已登记：情感/方言/语速控制），把检测结果翻译成 instruct 指令传给 TTS | 本地主路径；备选 **EmotiVoice（Apache-2.0）** 或 **GPT-SoVITS（MIT）**。**ChatTTS 代码 AGPLv3 + 模型 CC BY-NC，禁止随产品分发**（§3.6） |

**约束**：情感信号进入 prompt 与 TTS 指令必须**留痕可见**（铁律 3 的情感面）；云端情感检测默认关闭（数据出境），走本地模型或 LLM 兜底。

### 5.5 护栏（Rails）与内容安全（备案，暂不排期）

三条铁律本质就是 rails，R4 之后如需显式化规则引擎，参考（许可证/维护见 §3.6）：

| 项目 | 规模 | 定位 |

理由很直接：现有代码里 ASR 只有 `mock / whisper`、TTS 只有 `mock / cosyvoice2`（`main.py:400/437` 的 choices），**没有任何云端实现**。既然首次默认预设是"云端"，那么**没有 R2a，"默认云端"根本跑不起来**；R2b 是 provider 扩展，不是首发阻塞项。

**过渡期口径（必须对外说清）**：R1 阶段（R2a 之前）实际只有本地链路可用，此时"默认云端"尚未兑现，首启向导应临时以"本地"为默认并明确说明"云端语音将在下个版本提供"。R2a 合并后才切换为"云端默认"。**不要在 R2a 之前宣称支持云端语音**。

**冲突隔离**：

- R1a 改 `graph.py` 的 `_append_history` / `_persist_session`；R2a 改 `_apply_runtime_settings`。**约定：R1a 不得修改 `_apply_runtime_settings` 方法体**，二者可在同一周期并行。
- R2a 的 2.7 / 2.11 / 2.12 与 R1c 1c.5 都动设置页/向导 UI。**约定：R2a 侧的 UI 任务以 R1c 1c.5 合并后的页面结构为基线**；若并行推进，R2a 先落数据与 IPC（sidecar / Rust 侧），UI 接线待 1c.5 落地后跟进，不得各自发明一套设置页布局。
- **依赖边补全**：`R1c → R2a(UI)`、`R1c → R3a(UI)`；R2a/R3a 的验收含 UI，不能按"R2a 只依赖 R1a"排期。

**为什么 R1b 必须排在 R1c/R1d/R1e 之前**：它是纯重构（零用户价值），混在功能里会让 review 无法区分"这行是新功能还是搬家"。拆完打 tag，作为后续稳定基线。

## 10. 工程规范与验收

### 10.1 开发纪律

- **四闸**（规范环境 = `sidecar/.venv`，cwd = `sidecar`；**严禁仓库根 `.venv`**）：
  `pytest -m "not heavy"` / `ruff check .` / `mypy` / `lint-imports`
- 依赖唯一来源分两处：**Python 侧** = `sidecar/pyproject.toml`，`uv.lock` 入库，变更必须同步锁（本计划新增 `jieba`）；**Rust 侧** = `src-tauri/Cargo.toml`（本计划新增 `cpal`，输出设备枚举用，与 uv.lock 无关）
- 提交约定：Conventional Commits（母文档 §15.4）
- 契约单一来源：Pydantic → TS 自动生成，`ipc:check` 挂 build 前
- mock 与真路分离：`ECHOES_SIDECAR_MOCK`，mock 不得泄漏进真路
- 测试基线：pytest 410 / cargo 38，新链路补测试，覆盖率门禁不降低

### 10.2 完成定义（DoD）

一条任务算完成，须同时满足：

1. 代码合入且四闸全过
2. 契约变更按 §9.1 定级并已登记
3. 测试覆盖新链路**含失败与降级路径**（尤其 §3.4）
4. 文档同步（本表 / ADR / 母文档变更记录）
5. 新增依赖/模型已在 §3.6 登记并通过 §10.8 许可证门禁
6. 对应 Release 验收口径可被演示验证

### 10.3 资源验收

桌面常驻应用与网页 demo 的分界线在这里：

| 指标 | 建议值 | 说明 |
|---|---|---|
| 空闲态 RSS（含 sidecar） | ≤ 1.5 GB | 注明测量条件：模型常驻 vs 懒加载分别测 |
| 空闲态 CPU | ≤ 1% | 托盘常驻不能烧电 |
| UI 可交互 | ≤ 3 s | 主窗口可操作，不等模型 |
| 首轮可说话 | ≤ 8 s（模型已加载/缓存）；模型首次加载 ≤ 30 s 单独计，超时须有进度、可中断 | 冷启动与首次下载分开验收 |
| 模型首次加载 | ≤ 30 s 且有进度、可中断 | 超时必须能取消 |
| DB 体积增长 | ≤ 5 MB / 千轮（`turn_chunk` 未启用） | 启用向量后另定基线：1024 维 float32 ≈ 4 KB/chunk，现口径必然回退 |

> 以上为**建议值**，首次实测后写入基线，后续 Release 不得回退超过 20%。

### 10.4 数据安全验收

| 项 | 要求 |
|---|---|
| 迁移前备份 | 空间 ≥ 库 ×1.2 才 `VACUUM INTO`；路径用户可见；备份失败不迁移 |
| 迁移失败 | 回滚 + 保留备份 + `MIGRATION_FAILED` + RECOVERY 页；不自动还原、不无限重试 |
| 备份轮转 | 保留最近 3 份 |
| 外键完整性 | `PRAGMA foreign_key_check` 返回空（尤其 0004 重建 voice 后） |
| FTS 完整性 | `INSERT INTO turn_fts(turn_fts) VALUES('integrity-check')` 返回空 |
| 崩溃一致性 | 杀进程后重启，`turn` 表无 `status='pending'` 残留（启动清洗置 failed；`user_text` 保留、`assistant_text` 为 NULL、`fail_reason='crash_cleanup'`） |
| 完成事件一致性 | `turn_complete` 发出后立刻 kill，重启后该 turn 仍为 `complete`（finish 先于事件 commit） |
| 删除语义 | FK=ON：删除有摘要会话成功；删除被绑定 voice 报 `VOICE_IN_USE`；`turn_memory_ref` 随 turn/fact 级联 |

| # | 判据 | 达成于 |
|---|---|---|
| 1 | 关掉应用，明天打开，昨天的对话还在（一字不差） | R1c |
| 2 | 插上耳机，能在设置里选到它并试听 | R1e |
| 3 | 不打开主窗口，能按一个键就说话 | R1d |

**现状基线：0 / 5。** 每完成一个 Release 更新此表，作为对外进度声明。

### 10.6 审核基线

审核以本文档 + `architecture.md` + `PROGRESS.md` + `docs/acceptance/` 为依据；当前 `docs/` 仅存本文档，恢复母文档前以本文档 §9.2 与各 Release 验收为准。按 Release 验收口径与 §10.5 五判据逐条核验，输出「已达成 / 部分达成 / 未达成 + 证据位置」表。

### 10.7 延迟与质量门禁

| 项 | 门禁 |
|---|---|
| time-to-first-audio | P50/P95 记录；回归不得劣化 > 20%（ADR-012 现状 2727ms vs 500ms 预算，先记录基线，不掩盖差距） |
| ASR | 中文固定测试集 WER；云端/本地分别记录 |
| TTS | 音色相似度 + 合成失败率；`ready` 态合成失败率 = 0 是铁律 |
| 记忆 | Grounding `unsupported_claims` 占比（v1.1 起）；v1.0 用 R3a 评测集回归 |
| 启动 | UI 可交互 / 首轮可说话 / 模型首次加载分别记录 |

> R2a「云端首包更小」的表述改为「以实测首包数据为准」；未测数字不写进验收。

### 10.8 开源许可证与模型权重门禁

| 类别 | 允许方式 | 处置 |
|---|---|---|
| MIT / Apache-2.0 / BSD | 可随安装包分发 | 保留版权与 NOTICE；排除企业版目录（如 LiteLLM `enterprise/`） |
| LGPL | 不默认打包 | 只允许用户自行安装的外部组件，或经法务确认的动态链接方案；edge-tts 归此类 |
| AGPL / CC BY-NC | **禁止随产品分发** | 仅个人实验；ChatTTS 归此类（代码 AGPLv3+，模型 CC BY-NC 4.0） |
| 自定义模型许可（Llama Community 等） | 单独登记 | 保留通知、使用限制与 MAU 条款；Llama Guard 归此类 |
| 模型权重 | 与代码许可证分开核 | 代码 MIT/Apache 不代表权重可商用；每个下载项登记 license/来源/版本 |

**规则**：
1. 新增依赖或模型必须先在 §3.6 登记，否则不得进 R2a/R2b/R4 验收。
2. 代码许可证与模型权重许可证分开审查；模型权重下载页的 license 必须留档。
3. 星数、下载量、榜单分数不作为选型依据；许可证、维护状态、中文适配、集成成本优先。
4. 发现许可证不兼容时，默认动作是**移除/替换**，不是在验收时补免责声明。
